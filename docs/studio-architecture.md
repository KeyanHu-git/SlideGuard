## 为什么重做

旧界面要求用户输入八组坐标和扩展值，自动紧边却不画最终框。初始手动框会裁掉四边各5%，预设名称也可能与实际配置不一致。测试通过只能证明已有算法，不能证明人能看懂、操作和确认输出。

## 边界

```text
QML Studio（输入手势、布局、场景图）
       ↓ commands / ↑ view state
StudioController（后台任务、不可变请求、结果与错误）
       ↓                         ↓
CropEditor（无Qt域模型）      Preview provider
       ↓                     ├─ Office 4000px作者参考图
CropSpec + shared geometry    ├─ Qt PDF按需重渲染交付PDF
       ↓                     └─ 最终透明PNG显示交付alpha
ExportService ← CLI / JSON
       ↓
PowerPoint broker → 图像恢复/裁剪 → 独立QA → 原子发布
```

选择 Qt Quick/QML，以场景图和纹理显示代替整页 QWidget/QPainter 重绘。保持 Python 内核，不引入另一个 Node/Rust 服务、监听端口或远程页面。Qt PDF 用于交付PDF的本地按需显示；Poppler和Chromium继续作为独立QA渲染器。不能让显示器给自己的显示结果签发保真证明。

Office 原生排版暂不替换。字体度量、阴影、虚线相位和遮挡关系是当前产品的保真依据。以后可以给原生导出增加后端协议，但 LibreOffice 或第三方 OOXML 渲染器必须先通过相同困难样本，不能静默成为等价替代。

Qt Quick 的能力依据：[场景图](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html)、[异步图像提供器](https://doc.qt.io/qtforpython-6/PySide6/QtQuick/QQuickImageProvider.html)、[Qt PDF](https://doc.qt.io/qtforpython-6/PySide6/QtPdf/QPdfDocument.html)。固定开发依赖为 PySide6 6.9.2，不为追逐版本号改变现有便携包的Qt基线。

## 交互约定

- 左侧显示当前文件/页面，中间是画布，右侧只放裁剪与输出。主操作、缩放和任务状态固定可见。
- 默认自动紧边。源参考必须来自4000px原生预览，自动检测调用现有 crop_pixels。蓝框是内容裁剪，绿框是扩展后输出。白底参考图不是最终透明图。
- 手柄拖动和框内移动直接改同一个 CropSpec。每个拖动作为一次撤销事务。缩放和平移只改视口，不改文档坐标。
- 常用边距用滑杆和0/1/2/5%按钮。联动默认开启，关闭后分别拖动四边滑杆。高级数字输入保留给精确操作，不作为必经步骤。
- 扩展仍按选区宽/高计算，并裁限在原幻灯片内。这是已有API语义；需要页外透明扩边时另建契约，不能擅自改单位。
- 自动边界是当前Office参考图上的确定性结果，不是对透明/白色内容的语义理解。真实白色物体、全白页和特殊背景仍需困难样本与覆盖检查。
- 参数检查、最终保真QA、产物完整性复核分别显示。预览有效不显示为“保真通过”。压缩版明确标注可能缩小和有损编码位图，完整版另列。

## 状态与文件

预览、参数检查、导出和包复核串行执行，运行期锁定文件、页码和文档参数。QML仅提交命令，后台在启动时深拷贝请求。完成结果绑定该请求；任何编辑都会撤销参数检查状态，既有结果仍标为上次导出。

预览失败立即清空图像与边界，不能显示上一个文件的图。后台异常必须转成界面错误。取消调用已有令牌；运行中关闭窗口需等线程安全结束。

源码固定在 src/slideguard/studio/；QML在其 qml/；测试放 tests/test_studio_*.py；设计放本文。开发环境与运行证据只放本机 SlideGuard 目录，不提交私人PPTX、渲染图、缓存或大二进制。
